# 第二版本（AI批改）

## 第一步：命名

**AI批改问题：**

**监测状态和控制运动不属于设别管理模块**

我的问题：**不是根据有哪些报文就设计哪些接口，不是根据通信的数据来设置接口，而是将为了实现模块职责拆分出的功能单元设置为接口**

还是**要从模块本身的职责出发，通过职责分析需要完成什么工作，可以拆分命名为什么接口**，而不是整个流程，也是因为我的经验少不了解设别管理的具体职责，或者说前期模块设计时，规划的不深刻不清晰

DeviceManager模块负责：

1. 设备是否存在

2. 设备是否在线

3. 设备类型

4. 设备状态的结果

重新设计接口：

```C
DeviceManager_Init()   //初始化

DeviceManager_Register()   //注册设备

DeviceManager_UpdateHeartbeat()   //更新心跳
 
DeviceManager_UpdateStatus()   //将接受来的信息  更新（或上传）到设备表的状态，这个接口只负责写入经过节点判断、主控读取 后得出的状态结果，不负责处理数据后做出判断的逻辑

DeviceManager_CheckOffline()   //检测离线

DeviceManager_FindNode()   //查询设备

DeviceManager_GetOnlineCount()   //获取在线数量

DeviceManager_GetNodeState()   //获取节点状态，接收节点发来的信息
```

**模块化设计里非常重要的一步：接口名尽量体现业务行为（如读取节点发送来的状态），而不是通信行为（接收某某报文）**

```C
DeviceManager_Init()

DeviceManager_Register()

DeviceManager_UpdateStatus()

DeviceManager_UpdateHeartbeat()

DeviceManager_CheckOffline()

DeviceManager_FindNode()

DeviceManager_GetNodeState()

DeviceManager_GetOnlineCount()
```
